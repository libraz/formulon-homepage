# 実行環境

Formulon は 1 つの計算コアを複数の実行環境から使えるようにします。数式の意味ではなく、どこに配置してどう動かすかで選びます。2 つの実行環境でワークブックの結果が変わる場合は、不具合か、文書化された互換性差分として扱います。

::: info 同じエンジン、異なる実行環境
WASM、Python、Native Node、CLI は共通の計算処理を使います。変わるのはパッケージ構成、ファイルアクセス、メモリ所有権、起動コスト、ホスト側のエラーの受け渡しです。
:::

| 実行環境 | 選ぶ条件 |
| --- | --- |
| [WASM](/ja/runtimes/wasm) | ブラウザ、ワーカー、ネイティブアドオン前提なしの Node |
| [Python](/ja/runtimes/python) | スクリプト、ノートブック、データパイプライン、一括再計算 |
| [Native Node](/ja/runtimes/node-native) | プラットフォーム別の `.node` アドオンを配置できる Node サービス |
| [CLI](/ja/runtimes/cli) | シェル処理、CI スナップショット、問題の再現 |
| [CI 回帰検査](/ja/runtimes/ci-regression) | 自動チェックでワークブック差分を取りたい場合 |

- ワークブックデータがブラウザにあり、アップロード時のプライバシーを守りたい場合や、サーバーに元ファイルを渡したくない場合は WASM を使います。
- 帳票生成、定期ジョブ、入力規則の検証、ノートブックには Python を使います。
- ネイティブ成果物を配置でき、WASM より低い起動コストが必要な Node サービスには Native Node を使います。
- 再現可能な不具合報告、CI スナップショット、単発の再計算チェックには CLI を使います。

## 互換性の確認

実行環境の選択だけでは Excel 互換性は保証できません。重要なワークブックで使う前に [互換性](/ja/compatibility/) を確認し、自分のファイルで検証してください。
