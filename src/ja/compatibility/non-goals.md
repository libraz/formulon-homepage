# 対象外の機能

意図的な境界です。エンジンを小さく検証しやすく保ち、対象外のワークブックに対しては曖昧さなく「対象外」と返せるようにします。

| 領域 | 理由 |
| --- | --- |
| VBA 実行 | セキュリティ。マクロのバイト列は保存時に保持するが実行しない。 |
| 旧 `.xls`（BIFF） | 対象は現行の Excel 365。`.xls` は OOXML 以前の世代に属する。 |
| グラフ / 図形の描画 | UI または文書描画層の責務であり、ヘッドレスエンジンの責務ではない。 |
| Power Query / DAX | スプレッドシート数式とは別言語・別実行モデル。 |
| 元シートまたは外部データからのピボットキャッシュ更新 | 対応済みのキャッシュの投影・取得は対象ですが、キャッシュの再構築には別の実行モデルが必要です。 |
| ライブ外部接続（OLE DB / Web / OData） | 本番実行を決定論的・オフラインに保つため。 |
| スプレッドシート UI | Formulon はヘッドレスです。UI は別の層で提供します。[`formulon-cell`](/ja/cell/) はブラウザへ埋め込める UI キットを提供します。 |

::: info 用語: ヘッドレスエンジン（headless engine）
描画機能もエンドユーザー UI も持たない計算エンジンです。ホストが呼び、人間は直接触りません。ヘッドレスであれば、サーバージョブ・ブラウザタブ・CLI・UI ライブラリのいずれでも同じ意味論で動かせます。
:::

## なぜ明示するのか

対象外の機能を曖昧にしておくと、対応範囲がにじみ、互換性の説明も不明確になります。「やらないこと」を明示すれば、次の判断ができます。

- Issue の切り分けを yes/no で判断できる
- 互換性の範囲を検証可能な形で保てる
- 利用者は別のツールで補う必要がある機能を把握できる

## 隣接ツール

- VBA / マクロ → Excel そのもの、またはホスト独自の自動化
- グラフ / 図形 → Formulon で保持し、描画は別ライブラリ
- Power Query → 上流で実行し、`.xlsx` を Formulon に渡す
- UI → [`formulon-cell`](/ja/cell/)（ブラウザ向けの表計算 UI キット）
