# ロケールプロファイル

Excel の挙動は完全にはロケール非依存ではありません。関数名・区切り文字・日付解析・文字幅・通貨・テキスト処理が、プラットフォームとロケールで変わることがあります。そのため Formulon は単一のグローバル互換モードではなく、名前付き **プロファイル** を公開します。

::: info 用語: compatibility profile（互換性プロファイル）
Excel ビルドとロケールの組に名前を付け、Formulon がそれと一致することを示す Oracle データを紐付けたものです。ロケール依存の関数挙動はこのプロファイルに従います。アプリやテストはホスト OS のロケールではなく、プロファイルを明示的に固定します。
:::

## 現在のプロファイル

| プロファイル | 状態 | 目的 |
| --- | --- | --- |
| `win-365-ja_JP` | 既定の実行ターゲット。Windows 版 Microsoft 365 の Excel で取得・検証した期待値データに使用 | 主な実行ターゲット。ワークブック単位（ピボット / 印刷）の Oracle 検証トラックでプライマリプロファイル |
| `mac-365-ja_JP` | 数式 / 条件付き書式 Oracle のプライマリ | 数式と条件付き書式の Oracle データセット |

数式と条件付き書式の検証は Mac Excel 365 ja-JP から再生成します。ワークブック単位の検証は Windows 版 Microsoft 365 の Excel で取得した期待値データから再生成し、`win-365-ja_JP` をプライマリプロファイルとして使います。

英語ロケールのプロファイルは、対応するゴールデンデータが用意できてから公開します。データが揃わないプロファイルは、未検証の互換性を示唆しないために非公開のままです。

## プロファイルが評価に与える影響

現在のプロファイルが制御する領域は次のとおりです。

- 文字列の照合と型変換（文字幅・かなの扱いを含む）
- `CODE()` / `CHAR()` の挙動
- 環境依存の `INFO()` / `CELL()` の値
- ピボットテーブルのラベルとレイアウトの既定値

保存された数式は英語の関数名と不変のパーサー文法を使います。関数名ヘルパーは表示用の名前を別に提供します。プロファイルを変更しても、保存済みの数式を翻訳したり、すべての Excel ロケール差を実装したりするわけではありません。

::: warning プロファイルを暗黙に切り替えない
同じ数式に見えても、別プロファイルで再計算すると結果が変わる場合があります。アプリや CI は対象プロファイルを保存し、起動時に期待するプロファイルと一致するか確認してください。
:::

## プロファイルの保存

各バインディング経由:

::: code-group

```ts [WASM / Native Node]
wb.setExcelProfileId('win-365-ja_JP')
const profile = wb.excelProfileId()
if (!profile.status.ok) throw new Error(profile.status.message)
const id = profile.value
```

```python [Python]
wb.set_excel_profile_id('win-365-ja_JP')
id = wb.excel_profile_id()
```

:::

プロファイルはワークブックの寿命に紐づく状態であり、ランタイムのグローバルフラグではありません。同じプロセス内のワークブックがそれぞれ別プロファイルを持って共存できます。プロファイルはファイルへシリアライズされないため、アプリケーション側で ID を保存し、読み込み後に再設定してください。プロファイルを変更すると数式は再計算待ちになりますが、その場では再計算されません。値を読む前に `recalc()` を呼び出してください。
