# formulon-mcp

`@libraz/formulon-mcp` は Formulon 用の stdio [MCP](https://modelcontextprotocol.io/) サーバーです。AI エージェントが型付きツールを使って `.xlsx` と `.xlsb` のワークブックを調べ、編集できます。サーバーは子プロセス内で Formulon の WASM エンジンを使い、開いたワークブックをセッションごとに分離して保持します。ワークブックの出力は保存ツールで書き込みます。プレビューツールは PNG や SVG のファイルも書き出せます。

テンプレートへの入力、レポートの書式設定、計算シートの確認、表の集計など、ワークブック自体を変更する作業に使います。セッションでは値と数式の読み取り、セルや構造の変更、再計算、範囲のプレビュー、保存を Excel なしで実行できます。

::: info MCP と stdio
MCP（Model Context Protocol）は JSON-RPC 経由で AI クライアントに型付きツールを提供します。stdio ではクライアントが `formulon-mcp` を子プロセスとして起動し、stdin と stdout でメッセージを交換します。サーバーは待ち受けポートを開きません。プロセス境界とサーバーのメソッド許可リストが制御の境界になります。
:::

## 典型的な依頼

エージェントへのプロンプトには、入力ワークブック、変更内容、出力パスを指定します。例:

> `input.xlsx` を開き、`Summary!B2` の請求月を変更し、再計算して `Summary!A1:H24` を確認用に描画し、編集結果を `out/next-month.xlsx` に保存してください。元ファイルは変更しないでください。

通常は次の経路を使います。

1. `formulon_open_workbook` でセッションを開きます。
2. シートを調べ、対象範囲を読み取ります。
3. `formulon_set_cells` または `formulon_set_range` で範囲を変更します。
4. 現在の数式結果が必要な時点で再計算します。
5. レイアウトを確認するときは `formulon_preview_range` を呼び出します。
6. `outputPath` を明示して保存し、セッションを閉じます。

次の作業にも対応します。

| 作業 | 最初に読むガイド |
| --- | --- |
| 数式と書式を保ったまま、毎月のテンプレートを埋める | [ワークフロー](/ja/mcp/workflow) |
| 明細、税、合計から請求書を新規作成する | [作成](/ja/mcp/authoring) |
| スクリーンショットからフォームを再現し、保存前に改ページを確認する | [レイアウトとプレビュー](/ja/mcp/layout-preview) |
| 計算表の数式抜けや不一致を確認する | [数式監査](/ja/mcp/formula-audit) |
| データ範囲をネイティブテーブル（Table）にして地域別に集計する | [テーブルとピボット](/ja/mcp/tables-pivots) |
| 専用ツールにないエンジンメソッドを使う | [高度な API](/ja/mcp/advanced) |

## 対象となるファイルと処理

`.xlsx` と `.xlsb` を読み込めます。入力パスを指定しない場合は `Sheet1` を持つ既定のワークブックを作ります。計算とファイル解析は `@libraz/formulon` に委譲し、MCP サーバーはそのパッケージを WASM として読み込みます。読み込んだエンジンのバージョンは `formulon_version` で確認できます。ドキュメントは特定のリリース番号を前提にしません。

シートは 0 始まりの番号または完全一致するシート名で指定します。数値の `row` と `col` は 0 始まりです。`Summary!B2` のような A1 参照は高レベルのセルツールで使えます。範囲読み取りとプレビューの A1 参照は、1 シート内の矩形範囲に限定されます。列全体、行全体、3-D 範囲は MCP の A1 パーサーで拒否されます。

通常の作業には高レベルツールを使い、インストール済み `Workbook` API が必要な場合は高度な経路を使います。高レベル呼び出しは入力を検証し、用途に合わせた JSON を返し、セッションの状態を管理します。`formulon_workbook_call` は明示的な許可リストに限定されるため、先に `formulon_workbook_api` でインストール済みのシグネチャと宣言を取得します。

## ファイルと保存

パスは MCP サーバープロセスの作業ディレクトリから解決されます。保存では常に `outputPath` を明示し、拡張子を選びます。

- `.xlsx` は、作成したテーブル、ピボットテーブル、コメント、印刷設定などを保持したい場合に適しています。
- `.xlsb` はバイナリ形式を選びます。応答の `losses` に延期、格下げ、削除された機能が示されます。
- 保存応答の `bytes` はファイル内容ではなくバイト数です。

ファイルを開いたときに読み取れなかった部分があると、`session.loadLosses` に読み込み診断が入ります。保存時に保持できなかった内容は `losses` に入ります。ラウンドトリップが無損失だと判断する前に、両方を確認してください。損失がある保存後はセッションが変更あり（dirty）のままになります。

## 境界

- サーバーはツールのエンドポイントです。対話的なスプレッドシート UI には [formulon-cell](/ja/cell/) を使います。
- 任意の JavaScript や任意の `Workbook` メソッドは実行しません。低レベル呼び出しは許可リスト内に限られます。
- 変更が成功しても、ワークブックの業務ルールが正しいとは限りません。数式監査は確認候補を返しますが、数式の修復や計算の正しさの証明は行いません。
- プレビューはサーバーによる近似描画です。寸法、数式、フォント、改ページ、警告を返しますが、Excel と異なるフォントや未対応機能の表示差が生じる場合があります。

セッションの契約は [ワークフロー](/ja/mcp/workflow) で確認し、正確なフィールドや応答形が必要なときは [ツールリファレンス](/ja/mcp/tools) を参照してください。
